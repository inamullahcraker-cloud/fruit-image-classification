# Fruit Image Classification

A deep learning project that classifies fruit images into different categories using PyTorch. The project includes model training, image prediction, and a FastAPI backend for serving predictions through an API.

## 1. Project Overview

Fruit Image Classification uses a convolutional neural network (CNN) to identify the type of fruit shown in an image.

For example, when a user uploads an image of an apple, the trained model processes the image and predicts its most likely class, along with a confidence score.

The project is designed with a modular structure so that model training, inference, configuration, and API deployment can be managed separately.

### Main Features

- **Image classification:** Predicts the fruit category from an image.
- **Deep learning:** Uses PyTorch to build and load the classification model.
- **Image preprocessing:** Resizes and normalizes images before prediction.
- **Confidence score:** Returns the model's confidence for its prediction.
- **REST API:** Uses FastAPI to expose the model through HTTP endpoints.
- **Interactive API documentation:** Allows users to test supported endpoints through Swagger UI.
- **Configurable settings:** Stores model and inference settings in a YAML configuration file.

## 4. Dataset

The project uses fruit images for supervised image classification. The training dataset should contain labeled images organized by class.

A common directory structure is:

```text
data/
├── train/
│   ├── Apple/
│   ├── Banana/
│   └── ...
├── val/
│   ├── Apple/
│   ├── Banana/
│   └── ...
└── test/
    ├── Apple/
    ├── Banana/
    └── ...
```

- **Training set:** Used to learn the model's parameters.
- **Validation set:** Used to monitor performance and help select a model.
- **Test set:** Used for final evaluation on data not used for training or model selection.

The project has used the Fruits-360 dataset. The exact classes and dataset version should match the data used to train the checkpoint.

Dataset source: [Fruits-360 on Kaggle](https://www.kaggle.com/datasets/moltean/fruits)

The dataset is not necessarily included in this repository. Download it separately and configure the correct dataset paths before training.

## 6. Model Artifacts and Configuration

The application needs a trained model checkpoint and the correct class mapping.

The checkpoint is typically a `.pth` file containing the model's learned weights. The class mapping connects each numerical output index to its corresponding fruit class.

For example, a mapping may look like this:

```json
{
  "Apple": 0,
  "Banana": 1
}
```

This is only an example. Use the exact mapping generated during your own training process.

The configuration file, `configs/config.yaml`, should point to the correct checkpoint and mapping files. For example:

```yaml
inference:
  checkpoint_path: artifacts/checkpoints/best_model.pth
  class_mapping: artifacts/class_to_idx.json
  confidence_threshold: 0.5
```

Your configuration may require additional settings, such as the model architecture and image size. Keep those settings consistent with the implementation and the model used during training.

**Important:** The model architecture, class ordering, image size, and preprocessing must match the training setup. Otherwise, loading may fail or predictions may be incorrect.

## 8. Making Predictions

The prediction workflow generally consists of the following steps:

1. Load the input image.
2. Convert it into the expected color format.
3. Resize and normalize it using the same preprocessing used during training.
4. Pass the image through the trained model.
5. Convert the model outputs into class probabilities.
6. Select the class with the highest probability.
7. Return the predicted class and confidence score.

The confidence threshold is configurable. Depending on the implementation, a prediction below the threshold may be marked as uncertain rather than returned as a confident classification.

### Example API Request

If the API provides an image-upload endpoint, you can test it through Swagger UI:

1. Open `/docs`.
2. Find the image prediction endpoint.
3. Click **Try it out**.
4. Upload a fruit image.
5. Execute the request.
6. Review the JSON response.

The exact endpoint path, request format, and response fields depend on the implemented API.

## 10. Evaluation

A classification model should be evaluated on a held-out test set.

Useful metrics include:

- **Accuracy:** The proportion of correctly classified images.
- **Precision:** How often predictions for a class are correct.
- **Recall:** How many actual images of a class are identified correctly.
- **F1-score:** A balance between precision and recall.
- **Confusion matrix:** Shows which classes are being confused with one another.

Testing on real-world photographs is also important. A model trained on clean, uniform-background fruit images may perform differently on photographs with complex backgrounds, shadows, unusual lighting, or partially hidden fruit.

## 11. Troubleshooting

### Checkpoint Not Found

Verify that the checkpoint exists at the configured path:

```bash
ls -lh artifacts/checkpoints/
```

Make sure the filename matches the configuration exactly.

### Class Mapping Not Found

Check the artifact directory:

```bash
ls -lh artifacts/
cat artifacts/class_to_idx.json
```

The file must have the expected name, contain valid JSON, and match the class indices used during training.

### Incorrect Predictions

Check the following:

- The checkpoint belongs to the intended model architecture.
- The class mapping matches the training run.
- The image size and preprocessing match training.
- The correct checkpoint is being loaded.
- The input image is suitable for the model's training domain.

### API Fails to Start

Check the terminal output for missing packages, invalid configuration values, incorrect import paths, and missing model artifacts.
